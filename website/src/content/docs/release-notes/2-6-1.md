**Released:** 2026-11-05

Kure Monitor 2.6.1 is a security and UX patch release that completes end-to-end multi-tenant namespace isolation across all dashboard tabs, WebSocket streams, and direct backend API routes, adds a searchable multi-select namespace dropdown to the Security Scanner tab, and streamlines pod failure lifecycle management.

### Headline Changes

- **Multi-Tenant Namespace Isolation Across All Tabs (KAN-102, KAN-103, KAN-104, KAN-106)**: Hardened backend API authorization and real-time WebSocket event filtering for team-scoped users across Pod Monitoring, Security Scanner, AI Advice, and Topology Diagram tabs.
- **Searchable Namespace Dropdown in Security Scanner (KAN-106)**: Replaced the plain-text namespace filter input in the Security Scan tab with a searchable multi-select dropdown showing all accessible namespaces with `Select All` and `Clear All` controls.
- **Simplified Pod Lifecycle & Retention Removal (KAN-102, KAN-103)**: Removed legacy pod failure history, ignored-pod states, mirror-pod TTL settings, and data retention background jobs to keep pod monitoring focused on active real-time cluster state.

## Multi-Tenant Namespace Isolation Fixes

Building on the Teams & Granular RBAC system introduced in 2.6.0, version 2.6.1 closes remaining authorization gaps across direct REST endpoints and real-time WebSocket broadcasts for namespace-restricted users:

### Pod Monitoring (KAN-102)
- **REST API Enforcement**: Enforced team namespace permission checks on `GET /api/pods/{pod_id}`, `GET /api/pods/{pod_id}/manifest`, `GET /api/pods/{pod_id}/node`, `GET /api/pods/live/{namespace}/{pod_name}/logs/stream`, and `POST /api/pods/{pod_id}/troubleshoot`.
- **Scoped WebSocket Broadcasts**: Per-connection namespace permissions are now resolved when WebSocket clients connect, ensuring `pod_failure`, `pod_update`, `pod_resolved`, and `solution_generated` events are only delivered to users permitted to view that namespace.

### Security Scanner (KAN-103)
- **Finding-Level Access Control**: Enforced `_check_finding_namespace_access` on `GET /api/security/findings/{finding_id}/manifest`, `POST /api/security/findings/{finding_id}/fix`, `DELETE /api/security/findings/{finding_id}`, and `PUT /api/security/findings/{finding_id}/restore`.
- **Real-Time Event Filtering**: Filtered incoming `security_finding` and `security_finding_deleted` WebSocket events on the frontend against the user's allowed namespaces.

### AI Advice (KAN-104)
- **Finding-Level Access Control**: Enforced `_check_advice_namespace_access` on `GET /api/advice/findings/{finding_id}`, `POST /api/advice/findings/{finding_id}/explain`, `DELETE /api/advice/findings/{finding_id}`, and `PUT /api/advice/findings/{finding_id}/restore`.
- **Scoped Scan & Finding Events**: Updated WebSocket broadcasting to extract the target namespace from `advice_scan_status` payloads, and updated the AI Advice panel to filter real-time `advice_finding`, `advice_finding_deleted`, and `advice_scan_status` events against both the user's allowed namespaces and the currently selected namespace filter.

### Topology Diagram & RBAC View (KAN-106)
- **Workload & Manifest Endpoints**: Enforced namespace permission checks on direct API calls to `GET /api/diagram/workloads/{ns}/{kind}`, `GET /api/diagram/workload/{ns}/{kind}/{name}`, and `GET /api/diagram/manifest/{ns}/{kind}/{name}`.
- **RBAC Roles & ClusterRoles**: Filtered `GET /api/diagram/roles` so namespace-restricted users only see `Role` resources within their allowed namespaces (and receive an empty `cluster_roles` list). Restricted `GET /api/diagram/role/{namespace}/{name}` to allowed namespaces and blocked `GET /api/diagram/clusterrole/{name}` (`403 Forbidden`) for users without cluster-wide namespace access.

## Security Scanner Searchable Namespace Dropdown

- Replaced the free-text namespace input on the **Security Scan** tab with a searchable multi-select **Namespace** dropdown (`KAN-106`).
- Automatically lists all namespaces the user has access to, supports instant search filtering, individual checkboxes, and one-click **Select All** / **Clear All** actions.
